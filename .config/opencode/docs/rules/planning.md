# Planning Protocol — New Features

Load this file when planning a new feature.

Plans are documents, not chat replies — the concise-chat style governs conversation, not plan content. Write plans completely.

Before writing the plan:

- State the project goal (as currently understood) and the context that motivates the feature.
- Present arguments against the feature (steelman the opposition): does it add complexity without serving the core goal? Could an existing capability cover it? Is now the right time?
- Conclude with an explicit alignment verdict: how the feature advances (or conflicts with) the project goal.
- Proceed only after the user confirms; if misaligned, propose alternatives or descoping.
